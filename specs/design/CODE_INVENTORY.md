# Code Inventory — SuaSaúde (as of 2026-08-20)

Generated by reading the actual codebase (not AGENTS.md claims) under `src/app`, `src/screens`, `src/components`, `src/navigation`, `src/constants`, `src/contexts`, `src/services`, `src/mocks`, `src/hooks`, and `amplify/`. No code was modified.

## 1. Routing / Navigation

- **Routing library confirmed: Expo Router** (`expo-router: ~6.0.24`), file-based, under `src/app/`. `app/_layout.tsx` renders a `Stack` with `headerShown: false` and explicitly lists top-level screens plus the `(app)` group.
- **`src/navigation/` is dead code.** It contains only a `.gitkeep` file — no navigators, no components. AGENTS.md's description of it as "illustrative/aspirational" is confirmed; it is entirely unused. All real navigation is Expo Router + `AppShell`/`BottomTabBar`.
- **Root Stack** (`src/app/_layout.tsx`), wrapped in `ThemeProvider > UserProvider > DocumentProvider`:
  - `index` → `src/app/index.tsx` (login/bootstrap route, renders `LoginScreen`)
  - `register` → `src/app/register.tsx` (`RegisterScreen`)
  - `confirm` → `src/app/confirm.tsx` (`ConfirmScreen`)
  - `forgot-password` → `src/app/forgot-password.tsx` (`ForgotPasswordScreen`)
  - `profile-setup` → `src/app/profile-setup.tsx` (`OnboardingScreen`)
  - `edit-profile` → `src/app/edit-profile.tsx` (`EditProfileScreen`)
  - `(app)` → `src/app/(app)/_layout.tsx` → renders `AppShell`
- Standalone (non-tab) stack routes rendered inside the root stack but outside `(app)`: `add-appointment.tsx` (`AddAppointmentScreen`), `add-exam.tsx` (`AddExamScreen`), `edit-appointment.tsx` (`EditAppointmentScreen`, param `id`). These aren't declared as explicit `<Stack.Screen>` entries in `_layout.tsx` but Expo Router picks them up automatically from the file tree.
- **`(app)` group** (tab shell), routes rendered via `AppShell`'s `<Slot />`:
  - `dashboard.tsx` → `HomeScreen` (uses `useDashboardData`, `useExamsData`, `useUserContext`)
  - `exams.tsx` → `ExamsScreen` (uses `useExamsData`)
  - `appointments.tsx` → `AgendaScreen` (uses `useAppointmentsData`)
  - `ai.tsx` → `ChatBotScreen`
  - `prevention.tsx` → `PreventionScreen` (uses `usePreventionData`)
  - `profile.tsx` → `ProfileScreen` (uses `useUserContext`, `useThemeContext`)
  - `document-detail.tsx` → `DocumentDetailScreen` (reads selected doc from `DocumentContext`; renders `null` if none selected — reachable only via prior navigation that sets the context, not a deep link)
- **Tab bar / shell**: `src/components/AppShell.tsx` renders `<Slot />` (the active `(app)` route) plus `<BottomTabBar>`. Tab config lives in `src/constants/navigation.ts` (`APP_TABS`: dashboard, exams, agenda→appointments, ai, prevention, profile) and `getActiveTabId(pathname)` derives the highlighted tab from the current path. `BottomTabBar.tsx` (`src/components/BottomTabBar.tsx`) renders each tab with Ionicons (outline when inactive, filled + `primarySoft` pill background when active), fully theme-reactive (NativeWind `dark:` classes) and safe-area aware. Tab switching uses `router.replace(tab.href)`.
- All 17 screen components in `src/screens/` are wired to at least one route — none are orphaned/unrouted (verified via grep of `from '@/screens'` across `src/app`).

## 3. Libraries in use (confirmed via `package.json` + imports)

- **Navigation**: `expo-router` (file-based). No React Navigation used directly (it's a peer dep of expo-router internally, not used by app code).
- **State management**: No Redux/Zustand/Recoil. State is local `useState`/`useEffect` plus three React Contexts (`UserContext`, `DocumentContext`, `ThemeContext`) and a small custom `useAsyncResource` hook (generic async-fetch-with-status wrapper) used by every data hook (`useExamsData`, `useDashboardData`, `useMedicinesData`, `usePreventionData`, `useProfileData`, `useAppointmentsData`).
- **Forms**: `react-hook-form` (^7.73.1) + `@hookform/resolvers` (^5.2.2) + `zod` (^4.3.6) for schema validation (see `src/validation/forms_profile_setup` referenced by onboarding/edit-profile routes).
- **HTTP / AWS calls**: `aws-amplify` (^6.16.4) — `aws-amplify/auth` (Cognito), `aws-amplify/data` (`generateClient<Schema>()` for DynamoDB models), `aws-amplify/storage` (`uploadData`, `getUrl`, `remove` for S3). `@aws-amplify/react-native` (^1.3.3) for RN-specific Amplify support. No separate fetch/axios/react-query library — all "real" backend calls go through Amplify's generated client; mocked features use plain in-memory/promise-based mock modules (`src/mocks/api/*`) with a simulated delay (`requestSimulator.ts`).
- **Styling**: **NativeWind confirmed** (`nativewind: ^4.2.3`, `tailwindcss: ^3.4.19`, `prettier-plugin-tailwindcss`). `tailwind.config.js` uses `nativewind/preset`, `darkMode: 'class'`, and extends `theme.colors` with `app` / `app-dark` namespaces sourced directly from `src/constants/themeTokens.json`. Custom `borderRadius.app`/`borderRadius.card`, custom `fontFamily.sans` (`Basic-Regular`, a custom font loaded via `expo-font`).
- **Date/time**: No dedicated date library (no `date-fns`/`dayjs`/`moment`). Dates are handled with native `Date` and manual string parsing/formatting (e.g. `awsDateToBrazilian`, `formatDateForDisplay` in `examService`, manual `YYYY-MM-DD ⇄ DD/MM/YYYY` conversions scattered in route/service files).
- **UI component libraries**: None (no React Native Paper, no Tamagui, no gluestack). All UI (`Button`, `Card`, `Badge`, `AuthInput`, `BottomSheet`, `CalendarPicker`, etc. — ~40 components in `src/components/`) is hand-built with NativeWind classes. Icons via `@expo/vector-icons` (Ionicons). `expo-linear-gradient`, `expo-image` also used for visual components.
- **Animation**: `react-native-reanimated` (~4.1.1) is a dependency but not confirmed as heavily used beyond default RN/Expo primitives (not deeply audited here).
- **Other notables**: `expo-document-picker`, `expo-file-system` (exam file upload flow), `uuid`, `zod` (also used outside forms for schema validation), `@react-native-async-storage/async-storage` (session cache, exam/appointment caches, theme persistence), `@react-native-community/netinfo`.

## 5. AWS integration today

- **Amplify bootstrap**: `src/services/amplify/configureAmplify.ts`, imported once at the top of `src/app/_layout.tsx`. Sets up RN polyfills (`react-native-get-random-values`, `react-native-url-polyfill/auto`), configures `Amplify.configure(outputs)` from `amplify_outputs.json`, and wires Cognito token storage to `AsyncStorage` via `cognitoUserPoolsTokenProvider.setKeyValueStorage`.
- **Data schema** (`amplify/data/resource.ts`, `defaultAuthorizationMode: 'userPool'`), combining three schemas, each restricted to `allow.owner()`:
  - `UserProfile` (`amplify/data/schemas/user.ts`): fullName, birthDate, sex (enum), weightKg, heightCm, isSmoker, sexuallyActive, physicalActivity, alcoholConsumption, pregnancy.
  - `MedicalDocument` (`amplify/data/schemas/medical-documents.ts`): documentType (enum exam/prescription), s3FileName, documentName, documentDate, expirationDate.
  - `Appointment` (`amplify/data/schemas/appointments.ts`): appointmentType (enum CONSULTA/EXAME/CIRURGIA), appointmentName, professionalName, scheduledAt, address, observations.
- **Cognito auth**: handled in `src/services/auth/` — `authFlow.ts`, `google-auth.ts`, `session.ts`, `userSessionService.ts`, `profileSetupStatus.ts` (checks if a `UserProfile` row exists to decide onboarding-complete), plus direct `aws-amplify/auth` calls (`getCurrentUser`) in route files (`index.tsx`, `profile-setup.tsx`).
- **DynamoDB (UserProfile)**: `UserContext` (`src/contexts/UserContext.tsx`) calls `client.models.UserProfile.list({})` directly on mount/refresh to hydrate the app-wide user profile (with an `AsyncStorage` cache-first read for instant paint), mapping `sex` → `gender`. `src/services/profileSetupRepository.ts` does the create/update (upsert) used by both onboarding and edit-profile routes.
- **DynamoDB (MedicalDocument) + S3**: `src/services/examService.ts` is the full CRUD+storage layer — `uploadData`/`getUrl`/`remove` from `aws-amplify/storage` for the S3 file, plus `client.models.MedicalDocument.create/update/delete`. `src/hooks/useExamsData.ts` is the read-side hook: fetches via `client.models.MedicalDocument.list()`, transforms DB rows into UI-shaped `MedicalDocument` objects, and caches the result in `AsyncStorage` (`@SuaSaude:examsCache`) with a manual cache-invalidation/refetch-callback mechanism (`invalidateExamsCache()`), used by `ExamsScreen`, `DashboardRoute` (recent exams), and `document-detail`/`DocumentContext`.
- **DynamoDB (Appointment)**: `src/services/appointmentService.ts` does full CRUD (`create`/`list`/`update`/`delete`) via `client.models.Appointment`. `src/hooks/useAppointmentsData.ts` + `src/hooks/appointmentsCache.ts` mirror the exams hook's cache/refetch pattern for appointments, feeding `AgendaScreen`.
- **DocumentContext** (`src/contexts/DocumentContext.tsx`): pure client-side state (no AWS calls) holding the currently-selected `MedicalDocument` so `document-detail` route can render it without a URL param round-trip.
